# Adil Bağa (Әділ баға) — Backend 2 (Data Layer)

Данный модуль содержит слой данных (**Data Layer**) для сервиса мониторинга и сравнения цен на социально значимые продукты питания в городе **Актау** (Мангистауская область, Казахстан), разработанного в рамках хакатона **Smart City Aktau**.

---

## 1. Архитектурные принципы

- **Snapshot-only архитектура**: каталоги розничных сетей парсятся и сопоставляются **один раз** до live demo.
- **Никаких runtime-запросов**: публичное API и UI не обращаются к внешним сайтам магазинов во время демонстрации.
- **Географический контекст**: строго город **Актау** (проверены `shop_id` для Dina, каталог и филиалы для Dana, локация для Fix Price).
- **Защита от ложных объединений**: строгие правила несовпадения объёма, жирности, бренда и категории гарантируют, что разные SKU никогда не объединяются в один товар.

---

## 2. Источники данных

1. **Dina Market (Гипермаркет 301, 33 мкр Актау)**:
   - Endpoint: GraphQL `https://backend.dinamarket.kz/api/v1.1/customer/graph` (`shop_id: "28"`).
   - Выгрузка: постраничная пагинация и целевые категории (молоко, хлеб, яйца, сахар, масло).
2. **Dana Market (Актау)**:
   - Endpoint: Каталог на движке Aspro 1C-Bitrix `https://dana-market.kz/catalog/`.
   - Выгрузка: HTTP GET + Cheerio HTML-парсер целевых разделов.
3. **Fix Price (Актау)**:
   - Источник: Снапшот проверенных социально значимых товаров Актау `data/snapshots/fixprice_aktau.json` (с реальными EAN-штрихкодами и ценами в тенге).

---

## 3. Схема данных (PostgreSQL / Prisma)

Схема базы данных описана в [`prisma/schema.prisma`](prisma/schema.prisma) и включает 7 моделей:

1. **`Store`**: Розничные сети (`DINA`, `DANA`, `FIX_PRICE`).
2. **`StoreLocation`**: Точки и филиалы магазинов с реальными координатами в микрорайонах Актау.
3. **`Category`**: Категории товаров с динамическими схемами фильтрации `filterSchema` (`milk`, `bread`, `eggs`, `sugar`, `oil`, `other`).
4. **`RawProduct`**: Исходные товары магазинов с сохранением полного сырого JSON-пейлоада (`rawPayload`).
5. **`CanonicalProduct`**: Канонический агрегированный товар Adil Bağa с нормализованными характеристиками (`volumeMl`, `weightGrams`, `fatPercent`, `breadType` и т.д.).
6. **`ProductMapping`**: Связка между сырым и каноническим товаром с указанием метода сопоставления (`barcode`, `deterministic`, `ai`, `manual`) и коэффициента уверенности (`matchConfidence`).
7. **`Offer`**: Предложение конкретного магазина с ценой (`price` в тенге), старой ценой и признаком наличия (`inStock`).

## 4. Быстрый старт и запуск скриптов

### 4.1 Установка зависимостей

```bash
cd backend
npm install
```

### 4.2 Переменные окружения

Скопируйте пример окружения:
```bash
cp .env.example .env
```
Укажите строку подключения к PostgreSQL в `DATABASE_URL` (например, для локального PostgreSQL или Supabase):
```env
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/adil_baga?schema=public"
```

### 4.3 База данных и миграции

```bash
# Генерация Prisma Client
npm run db:generate

# Применение миграций к БД
npm run db:migrate

# Сидирование БД готовым снапшотом Актау (филиалы, категории, канонические товары и офферы)
npm run db:seed
```

### 4.4 Пайплайн сбора и сопоставления данных

```bash
# Запуск полного цикла (парсинг Dina, Dana, Fix Price + нормализация + сопоставление)
npm run data:pipeline

# Вывод отчёта о качестве данных и ценовом разбросе
npm run data:report
```

### 4.5 Тестирование и верификация

```bash
# Комплексный аудит-тест (38 тестов: нормализация, SKU rules, геоданные Актау, DTO, целостность снапшота)
npm run test:audit

# Юнит-тесты алгоритма сопоставления товаров
npm run test:matching
```

## 6. Контракт передачи данных для Backend 1 и Frontend

Backend 1 (NestJS API) работает с уже наполненными таблицами базы данных PostgreSQL:
- `CanonicalProduct` и отсортированные `Offer` по возрастанию цены (`price ASC`).
- `StoreLocation` для гео-поиска ближайшего магазина с минимальной ценой по координатам пользователя.
- `Category` и `filterSchema` для динамических фильтров в каталоге (жирность, объём, бренд).

*Все данные автономны и воспроизводимы через `npm run db:seed`.*
