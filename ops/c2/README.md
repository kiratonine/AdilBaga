# C2 inactive provisioning kit (Part25)

This is an installation candidate, not production authorization. Default
`node scripts/ops/c2-provisioning-plan.mjs` performs no file/env/network reads.
No automatic service, publisher hook, observation or cache invalidation exists
in this kit. Existing [C2 custody/SLA](../../docs/production/FRONTEND_REVALIDATION.md)
and [backup tools](../postgres/README.md) remain unchanged.

## Recovery: one private Owner input procedure

Owner supplies **one existing approved dedicated read-only operator context**
through a local private file, outside every source checkout. Do not send it in
chat. File owner is the executing operator, 0600, single link, no symlinks;
ancestor directories root/operator-controlled, no effective group/other write
(root sticky temporary ancestor allowed). Storage and existing GPG home must be
separate owned 0700 directories outside source. No value is discovered or copied
from API/ingest env. No credential/key is generated by the validator.

Exactly four unquoted `NAME=value` lines, final LF; no shell syntax, expansion,
comments, duplicate names, multiline values or whitespace. URI-encode reserved
characters. Keys: `BACKUP_DATABASE_URL`, `BACKUP_OUTPUT_DIR`, `BACKUP_GPG_HOME`,
`BACKUP_GPG_RECIPIENT`. DSN must use `sslmode=verify-full`; recipient is full
40/64 hexadecimal fingerprint. The stricter operator validator does not relax
the existing backup guard. Explicit check reads only that file and those two
directories; tool probes are bounded and their output suppressed:

```bash
node scripts/ops/prepare-recovery-operator.mjs --check "$OWNER_OPERATOR_HANDLE"
```

Default/`--offline` never reads env, files or network and returns
`MISSING_OPERATOR_INPUT`. Explicit check emits only `READY`,
`MISSING_OPERATOR_INPUT`, `INVALID_CUSTODY`, `BLOCKED`; non-READY exits 1.
READY is **configuration readiness**, not DB identity, connectivity or parity.
The parser never `source`s/evaluates dotenv; do not log its returned object.

Before backup, the independently approved operator must establish in a bounded
READ ONLY transaction: real session/current role identity; no superuser,
CREATEDB, CREATEROLE, REPLICATION or BYPASSRLS; no effective write/DDL role
membership or public schema CREATE; full public-table SELECT sufficient for
pg_dump; finite connect/statement/lock deadlines. Inspect all effective roles,
not a role-name guess. Record latest published snapshot/as-of separately from
API dashboard.snapshotAt. If suitability cannot be proved, STOP. This CLI
deliberately does not connect to the database or certify role privileges.

After those gates, this runnable packet passes the parsed configuration only
to unchanged backup tooling, with no DSN in argv or raw child output:

```bash
set +x
node --input-type=module - "$OWNER_OPERATOR_HANDLE" <<'JS'
import { checkOperator, readOperatorContext } from './scripts/ops/prepare-recovery-operator.mjs';
import { spawnSync } from 'node:child_process';
if (checkOperator(process.argv[2]) !== 'READY') process.exit(1);
const values = readOperatorContext(process.argv[2]);
const r = spawnSync('/usr/bin/timeout', ['--signal=TERM', '--kill-after=5s', '420s', '/bin/bash', 'ops/postgres/backup.sh'], {
  env: { PATH: process.env.PATH, ...values }, stdio: 'ignore',
});
console.log(r.status === 0 ? 'BACKUP_COMPLETED' : 'BLOCKED');
process.exitCode = r.status === 0 ? 0 : 1;
JS
```

Keep the file/context in exclusive operator custody through execution. Use the
unchanged guarded [restore procedure](../postgres/README.md) on a **new**
loopback PG17 `part11_*` target, local NOLOGIN role prerequisites, no production
credentials. Verify checksum/custom format/exit0, ten table counts, snapshot and
SourceRun history, migrations/checksums, RLS/policies/constraints/indexes/orphans
and restricted local Go smoke. Use unchanged
[`pm-audit-v1`](../../scripts/perf/product-mappings-audit.sql) for binary-safe
source/target comparison for the same recovery point. No matching source proof
means `RESTORE_VERIFIED_SOURCE_PARITY_PENDING`, never full parity. Clean only
owned local plaintext/disposable resources; never prune older backups.

## Independent C2 approval packet

Owner independently reviews **one packet**, not an uploader's `approved` flag:

1. Full immutable source commit, Go1.27.2 build recipe, linux/amd64 binary
   digests, five exact Node module hashes, installer hash and test evidence.
2. Separate actual Vercel READY Production alias `aktau.market`, deployment ID,
   frontend SHA and timestamp proof for each attempt; no guessed source=deploy.
3. Dedicated restricted reader handle and actual least-privilege identity proof,
   plus Backend2 permission for its private C2 namespace and BEFORE hook.

Build in a clean immutable source checkout, outside production. Projection:
`CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-X main.sourceSHA=$SOURCE_SHA" -o "$BUNDLE/c2projection" ./cmd/c2projection`;
clock: same CGO/GOOS/GOARCH, `go build -trimpath -o "$BUNDLE/relayprobe" ./internal/revalidation/testdata/relayprobe`.
Five Node modules listed by `NODE_FILES` in the plan are copied unchanged from
that Git object. Include `source-manifest.json`, canonical compact JSON + LF,
exact keys/order `sourceSha`, `recipe`, `nodeMajor`; recipe is the exported
`BUILD_RECIPE` string and nodeMajor is 24. This public manifest is NOT approval.

```bash
node scripts/ops/c2-provisioning-plan.mjs --review-bundle "$BUNDLE" "$SOURCE_SHA"
```

Inspection checks exact inventory, regular single-linked nonwritable files,
ELF64 little-endian amd64, digests and exact Node bytes from that Git commit.
Its output `REVIEW_REQUIRED_NOT_APPROVAL` cannot authorize installation.
Independent approval must verify binary build provenance, not just ELF magic or
uploader hashes. Compare source SHA against the currently approved release; a
source-manifest/approval mismatch fails closed. No network fetch inside installer.

## Root guard: no-clobber, inactive installation

An independently authorized administrator stages the reviewed installer itself
in a root-controlled directory (no operator-writable ancestors), the **exact**
public bundle in `/var/lib/aktau-c2-install/bundle`, and independent approval in
`/etc/aktau-c2-install/approval.json`, root:root 0600. Parents must already exist,
root-controlled and not effectively writable by nonroot (ACL mask included).
The guard never creates these trust inputs or broadens privileges. No new sudo
grant is part of this kit. Installer invocation uses the existing admin channel.

Approval is canonical JSON + LF with exact keys `version`, `authorization`,
`files`, `operatorUid`, `recipe`, `nodeMajor`. Version1/Node24; positive existing
operator UID >=1000; recipe exactly `BUILD_RECIPE`. `files` maps the two ELF,
five Node filenames and `source-manifest.json` to SHA256. `authorization` is
the **independently supplied** existing provider record, exact fields: version1,
Owner-approved boolean, sourceSha40, binarySha25664, clockSha25664, safe buildId,
platform linux/amd64. The installer copies this attestation; it does not approve
its own build. Unknown keys (including caller deployment attestation), files,
links, unsafe ownership/modes, malformed/duplicate JSON, mismatched digests or
stale source against approval reject before writes.

After independent custody approval, root runs the reviewed root-controlled
installer with `--verify`, then **once** `--install`. Fixed destination allowlist:

- `/usr/local/libexec/aktau-c2`: root0755; ELF0555, Node/source manifest0444.
- `/etc/aktau-c2`: root0755; copied independent authorization0644.
- `/var/lib/aktau-sync/c2`: approved existing operator0700; empty ledger0700.

Every target must be absent. No overwrite/merge, symlink traversal, shell,
service commands, SQL, network, secrets, env loading or generic path arguments.
Pinned parent descriptors, no-follow opens, read-once verified bundle bytes,
short-write loops, file+directory fsync and Linux renameat2(NOREPLACE) protect
installation. Root must remain trusted. The fixed root receipt is
`/etc/aktau-c2-install/receipt.jsonl`, 0600, fsynced before publication. Failure
leaves a recovery interlock; **never retry install over partial state**.

This creates **inactive resources only**. It does not create `reader.dsn`,
`deployment.json`, attempt FIFO, services or hooks. Those need separate
independent existing authority. No Go API/Telegram/runtime deployment occurs.

## Rollback and crash handling

Use the same root-controlled guard `--rollback` before activation. It verifies
the original independent approval hash, receipt, exact inode/device and every
byte/inventory before removing **only its own** new trees. A recorded interrupted
private stage may contain a prefix/subset of approved files. Rollback refuses
foreign files, live ledger entries, reader credentials, deployment attestation,
changed approval or mutated state, rather than removing operator data. No old
target, service, backup or key is removed. A torn receipt or interruption before
durable intent is ambiguous: STOP for independent manual reconciliation; never
guess ownership from a directory name. No automatic stale-lock cleanup.

## Backend2 genuine-publication boundary (pending, not implemented)

Current `cmd/ingest` performs `engine.Stage()` before `PublishThenNotify`, and
post-COMMIT notifier relay reads `C2_EVENT_FIFO` / `C2_EVENT_ATTEMPT_ID`. Adding
BEFORE only immediately before Publish is **too late**: canonical mutations can
already occur during Stage. Independent Backend2 integration must obtain trusted
S0/witness **before any canonical mutation**, arm persistent FIFO reader with
the new attempt ID, then allow the already-legitimate publisher to proceed.
Observer failure must not block/slow ingestion; an unready attempt is excluded,
not a publication failure. No polling scheduler or extra notification is added.

Use existing `prepareObservation → observe → finalize`, private provider/capture
registry, no fixtureOnly bypass. Exact chain S0 → actual S1 COMMIT/204 FIFO →
AFTER S1/S0, stable deployment/frontend identity, independent cleanup proof.
BEFORE/deployment/FIFO per-attempt setup must use independently authorized
operator integration; there is no readiness-return hook added to the existing
supervisor here. Without a verified bounded integration, **do not activate**.
Keep 35-minute supervision, one 5s SLA, <=20s diagnostics, <=21 GET/2 sitemap;
three genuine qualified PASS, FAIL resets, INCONCLUSIVE does not count. No
artificial sync, HMAC POST, fabricated snapshots or live observer in tests.
