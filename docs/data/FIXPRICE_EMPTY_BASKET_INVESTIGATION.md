# Fix Price: пустые позиции в «Стоимости продуктовой корзины» — расследование

Дата: 2026-10-20. Тип работы: только анализ, ни код, ни прод не менялись.

## Симптом

На дашборде в блоке «Стоимость продуктовой корзины» у Fix Price:

| Позиция | Dana Market | Dina Market | Fix Price |
|---|---|---|---|
| Молочные продукты (1 л) | 537 ₸ | 499 ₸ | 699 ₸ (Молоко АЙНАЛАЙЫН 2.5% 1л) |
| Сахар (1 кг) | 483 ₸ | 853 ₸ | — «нет в сети» |
| Растительные масла (1 л) | 920 ₸ | 809 ₸ | — «нет в сети» |
| **Итог** | **1 940 ₸** (выгоднее всего) | 2 161 ₸ | **699 ₸**, «Нет 2 из 3 позиций» |

## Что проверено

1. **Живой API Fix Price** (`api.fix-price.kz/buyer/v1`, `x-city: 1594`, `x-country: 3`, только чтение):
   - категория `produkty-i-napitki`: `x-count: 871` товаров;
   - подкатегории `chay-kofe-sakhar` (82), `bakaleya` (85), `zapravki-sousy-pripravy` (8) просмотрены полностью.
2. **Прод БД (Supabase, проект `adil-baga`)**: два SELECT по текущему опубликованному снапшоту (published 2026-10-20 01:02:09 UTC).
3. **Код**: скрапер [`pipeline/src/scrapers/fixprice.ts`](../../pipeline/src/scrapers/fixprice.ts), SQL дашборда [`backend-go/internal/postgres/dashboard.go`](../../backend-go/internal/postgres/dashboard.go), контракт [`contracts/openapi.yaml`](../../contracts/openapi.yaml), компонент [`frontend/src/components/dashboard/Baskets.tsx`](../../frontend/src/components/dashboard/Baskets.tsx).

## Выводы

### 1. Сахар: товара в ассортименте нет

В подкатегории «Чай, кофе, сахар» и в «Бакалее» Fix Price Актау сахара нет ни в какой фасовке, только чай, кофе и цикорий. Единственное совпадение по слову «сахар» — «Воздушный рис в сахарном сиропе». Значит, «нет в сети» здесь **верно**, это не баг пайплайна.

### 2. Масло: товар есть и лежит в БД, но корзина его отсекает (основная причина)

- API: «Масло подсолнечное рафинированное, Миладора, 0,9 л», 799 ₸, `inStock: 9`.
- Прод БД, текущий снапшот: canonical product «Масло подсолнечное рафинированное Миладора 0,9 л», категория `oil`, `attributes.volumeMl = 900`, offer 799 ₸, `inStock = true`.

Скрапинг, разбор объёма, категоризация и публикация отработали правильно.

Причина в SQL дашборда ([`dashboard.go:26-34`](../../backend-go/internal/postgres/dashboard.go)): слоты корзины требуют **точного** совпадения атрибута.

```sql
slots(ord,slug,name,key,value) AS (
 VALUES (1,'milk','Молочные продукты','volumeMl','1000'::jsonb),
        (2,'sugar','Сахар','weightGrams','1000'::jsonb),
        (3,'oil','Растительные масла','volumeMl','1000'::jsonb)
), candidates AS (
 ... JOIN slots ON slots.slug=c.slug AND u.attributes->slots.key=slots.value
```

`900 ≠ 1000`, поэтому кандидата нет, и позиция приходит с `productId/name/price = null`. Это поведение закреплено в контракте ([`openapi.yaml:150-153`](../../contracts/openapi.yaml)): «milk volumeMl=1000, sugar weightGrams=1000, oil volumeMl=1000, without category fallback».

Молоко у Fix Price в корзину попало только потому, что «АЙНАЛАЙЫН 2.5%» ровно 1 л.

### 3. Отображение частичной суммы

- Бэк считает `total = sum(coalesce(best.price, 0))`: пустые позиции дают 0, так что итог Fix Price = 699 ₸.
- Фронт уже обрабатывает это корректно в главном: «Выгоднее всего» выбирается только среди **полных** корзин (на скрине это Dana), а полностью пустая корзина показывается как «нет данных».
- Остаётся косметика: у **частично** заполненной корзины крупно показано 699 ₸ рядом с 1 940 / 2 161 ₸. Подпись «Нет 2 из 3 позиций» есть, но визуально число выглядит как самая дешёвая корзина.

### Общий контекст

Число offers в текущем снапшоте по сетям:

| Сеть | Offers | Категорий |
|---|---|---|
| Dina | 2004 | 9 |
| Dana | 1178 | 9 |
| Fix Price | 74 | 5 |

Fix Price не продуктовый ритейлер, базовых продуктов у него мало, поэтому пустые слоты у него будут случаться и дальше. Это свойство источника, а не регрессия.

## Как решить

### Вариант 1. Слот по диапазону фасовки с ценой за единицу (бэк)

**Где:** только бэк. Фронт получает уже выбранный товар и других кандидатов не видит.

**Что изменить в `dashboardSQL`:**

1. Заменить точное совпадение на диапазон, например 800–1200 мл/г:
   ```sql
   slots(ord,slug,name,key,target,min_v,max_v) AS (
     VALUES (1,'milk','Молочные продукты','volumeMl',1000,800,1200),
            (2,'sugar','Сахар','weightGrams',1000,800,1200),
            (3,'oil','Растительные масла','volumeMl',1000,800,1200)
   ), candidates AS (
     SELECT ..., (u.attributes->>slots.key)::numeric AS size,
            u.price * slots.target / (u.attributes->>slots.key)::numeric AS unit_price,
            row_number() OVER (PARTITION BY u."storeId", slots.ord
                               ORDER BY u.price * slots.target / (u.attributes->>slots.key)::numeric, u.id COLLATE "C") choice
     FROM usable u JOIN public.categories c ON c.id=u."categoryId"
     JOIN slots ON slots.slug=c.slug
      AND jsonb_typeof(u.attributes->slots.key)='number'
      AND (u.attributes->>slots.key)::numeric BETWEEN slots.min_v AND slots.max_v
   )
   ```
2. Решить, что суммировать в `total`: **цену, приведённую к 1 л/1 кг** (`unit_price`, честное сравнение корзин; рекомендуется) или фактическую цену полки (`price`, проще для пользователя, но 0,9 л против 1 л — неравное сравнение).
3. Отдавать в `BasketItem` дополнительно фасовку (`size`) и, при варианте с `unit_price`, фактическую цену полки. Это новые nullable-поля, обратно совместимы.
4. Обновить описание в `contracts/openapi.yaml` (убрать «volumeMl=1000 … without category fallback», описать диапазон и правило цены).
5. Тесты: `backend-go` (integration fixture с товаром 900 мл и с товаром за пределами диапазона), фронтовый `DashboardPage.test.tsx` при изменении контракта.

**Ожидаемый эффект:** у Fix Price в слоте масла появится Миладора 0,9 л (≈888 ₸/л или 799 ₸ — в зависимости от п. 2). У Dana и Dina в слоты могут попасть более дешёвые фасовки 0,8–0,9 л, и их итоги тоже изменятся. Это нужно согласовать с владельцем продукта как изменение бизнес-правила.

**Ограничения:** правка Go API и деплой контейнера вне scope Backend 2, нужно отдельное разрешение владельца. Миграции не требуются.

### Вариант 2. Честное отображение частичной корзины (фронт, косметика)

**Где:** фронт, [`Baskets.tsx`](../../frontend/src/components/dashboard/Baskets.tsx). Бэк менять не нужно: контракт уже отдаёт `price: null` для отсутствующих позиций.

Уже сделано: исключение неполных корзин из «Выгоднее всего», «нет данных» для пустой корзины, подпись «Нет N из M позиций».

Осталось (одно на выбор):
- приглушать итог неполной корзины так же, как у пустой (`text-muted`), без акцента;
- или подписывать прямо в итоге: «699 ₸ · 1 из 3 позиций»;
- или вместо суммы показывать «неполная корзина», а частичную сумму оставить только в «Составе корзины».

Плюс тест в `DashboardPage.test.tsx` на частичную корзину.

### Что не решается ничем

Сахар у Fix Price не появится, пока сеть его не продаёт. Для этой позиции единственно правильное поведение — «нет в сети» и аккуратное отображение (вариант 2).

## Рекомендация

1. Вариант 2 сделать сразу: малая правка фронта, без рисков, деплой фронта.
2. Вариант 1 согласовать с владельцем как изменение бизнес-правила корзины (диапазон, правило цены), затем сделать на бэке с обновлением контракта и деплоем Go API по отдельному разрешению.
