## 6. Известные ограничения

- Фильтр охвата грубый, по категориям: в «кисломолочных» попадают десерты и пудинги, в «хлебе» — торты и печенье, в «крупах» — хлопья и супы. Точнее — белый список типов товара (тип сейчас не хранится в словаре).
- Топ «разброса цен» на дашборде содержит выбросы: весовые овощи и зелень с разными единицами цены, отдельные ложные совпадения (например, Colgate, Kinder 3,5 кг).
- Слот корзины «сахар» берёт самый дешёвый товар категории `sugar` («Сахар и соль»), на тесте это была соль 45 ₸.
- Fix Price в охвате представлен 75 товарами (его ассортимент в основном нетоварный).
- Без картинки у ~14% карточек в охвате: у Dina в API нет изображений для части товаров.

## 11. Предложение для Backend1: пустая категория `other`

В production есть легаси-категория `other` (создана baseline, на неё ссылаются старые canonical). После публикации нового snapshot она будет пустой, но `/api/categories` её вернёт. Удалить строку нельзя: FK `canonical_products.categoryId ON DELETE CASCADE` удалит историю baseline.

> Предложение: `ListCategories` возвращает только категории, у которых есть `inStock` оффер с `price>0` в текущем published snapshot (тот же `EXISTS`, что в `discoverySQL`, `categories.go:69-74`). Это изменение семантики API v1, нужно одобрение Backend1/Дениса. До этого `other` в production будет пустой страницей.

Также: подпись слота корзины «Сахар и соль» зашита в `dashboard.go`; после выноса соли её стоит заменить на «Сахар» (изменение Go, не сделано).
