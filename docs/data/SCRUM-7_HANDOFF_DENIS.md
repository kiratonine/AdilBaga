## Как сделано — по твоим голосовым

- **LLM использовался один раз.** Раскладка по категориям и сопоставление сделаны на бесплатных ключах Gemini плюс Claude. Результат сохранён в git как словарь `data/mapping/dictionary.json`: `магазин:id товара → карточка`. Так «молоко FoodMaster» и «FoodMaster молоко» — одна карточка, а 3.2% и 1.5% — разные.
- **Ежедневно работает обычный код, без AI** — `pnpm sync`. Адаптеры магазинов → словарь → Go `cmd/ingest`. Известный товар получает новую цену, незнакомый публикуется отдельной карточкой и попадает в `data/sync/unmapped.json`. Готов скрипт `pipeline/scripts/daily-sync.sh` и инструкция для cron/systemd (`docs/data/SYNC_RUNBOOK.md`) — под твой сервер из SCRUM-8.
- **Fix Price теперь идёт через их API** (Актау = `x-city: 1594`), а не через ручной файл.
- **Проверено:** все тесты зелёные (pipeline 68, Go — все пакеты). Повторный `sync` на тех же данных не создаёт ни одной новой карточки. 50 случайных групп проверены вручную.

## Что нужно исправить до загрузки в прод

1. **Корзина «сахар» берёт соль.** Категория `sugar` — это «Сахар и соль», и слот корзины выбрал соль за 45 ₸. Нужно разделить сахар и соль.
2. **Выбросы в «разбросе цен» на дашборде:**
   - весовые овощи и зелень сравниваются с разными единицами (за кг и за штуку);
   - есть единичные ложные совпадения (Colgate, Kinder 3,5 кг).
   Нужно убрать весовые товары из сравнения и вручную пройти топ разбросов.
3. **«Неуверенные» сопоставления видны на сайте как обычные.** Это ~290 пар с уверенностью 0.80–0.94, а API на статус `pending` не смотрит. Нужно решить: проверяем их руками или API показывает только подтверждённые.
4. **Ручная сверка цен с сайтами не сделана** (по плану нужно по 3 цены на магазин).
5. **Фильтр «продукты питания» грубый.** В «хлеб» попадают торты, в «кисломолочку» — пудинги. Лучше фильтровать по типу товара.
