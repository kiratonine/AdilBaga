## 1. Сводка результатов (Executive Summary)

В ходе реализации плана работ по документу `BACKEND_2_DATA_QUALITY_FIXES_AFTER_PART_05.md` были устранены все выявленные дефекты качества данных без изменения контрактов Backend 1 и без искусственных/фейковых товаров:

1. **P0 — DINA Ingestion Coverage & Target Search:**
   * **Root Cause:** В GraphQL API сети «Дина» метод `searchProducts` требовал типизированный объект переменной `searchQuery: SearchQuery!`, где ключевое поле — `search`. Прежний код передавал плоский аргумент `query: $query`, из-за чего Apollo Server возвращал ошибку `Unknown argument "query"`, которая глушилась пустым `catch {}`.
   * **Исправление:** Запрос обновлен на строгий GraphQL-контракт: `searchProducts(shop_id: $shopId, searchQuery: { search: $kw })`. Добавлен целевой поиск по ключевым категориям корзины (`молоко`, `сахар`, `масло подсолнечное`, `хлеб`, `яйца`, `nemoloko`, `эконива`, `достык`, `савушкин`). Ошибки логируются через `console.warn` без silent catch.
   * **Результат:** Количество товаров DINA выросло со 144 до **563**. Целевые demo-категории полностью наполнены реальными товарами.

2. **P0 — Weighted-Price Normalization (`Банан = 1 ₸`):**
   * **Root Cause:** DINA API отдает весовые товары (`price_type: "weight"`, `isWeightProduct: true`) с ценой за грамм (`0.7 ₸/г`). Старый парсер делал `Math.round(0.7) = 1 ₸`.
   * **Исправление:** Реализовано нормализационное правило: цена домножается на `1000` (для получения KZT за 1 кг) либо на граммовку из названия. `0.7 ₸/г → 700 ₸/кг`, `oldPrice 0.9 → 900 ₸/кг`.
   * Добавлены unit-тесты, подтверждающие корректность пересчета для весовых позиций и сохранность цен для штучных товаров. В новом снапшоте товаров с ценой `<= 10 ₸` ровно **0**.

3. **P1 — Сохранение атрибута `packageCount`:**
   * **Root Cause:** `NormalizerService` извлекал `packageCount` (например, `20 шт`), но `MatcherService` в `newGroup.attributes` не передавал это поле. В результате в `CanonicalProduct.attributes` поле отсутствовало, а runtime-фильтр `/api/categories/eggs/filters` возвращал пустые опции.
   * **Исправление:** 
     * `packageCount` добавлен в `MatchGroup.attributes` и в `buildFingerprint`.
     * В `canMatch` подтверждено строгое правило защиты от склейки разных фасовок (`10 шт != 20 шт`).
     * В схему фильтров `Category.filterSchema` для категории `eggs` добавлена опция `20`: `options: [10, 15, 20, 30]`.
   * В новом снапшоте атрибут `packageCount` сохранен у **42 канонических продуктов**.

4. **P1 — Изображения DINA (`imageUrl`):**
   * **Исследование API:** В схеме GraphQL типа `Product` выявлены поля `preview { url }` и `images { url }`. Проверено, что URL отдают изображения (HTTP 200, JPEG) без авторизации.
   * **Исправление:** `DinaScraper` извлекает `imageUrl = item.preview?.url || item.images?.[0]?.url || null`.
   * Покрытие изображениями у DINA выросло с **0% (0 / 144)** до **95% (536 / 563)**!

5. **P1 — Кросс-сетевое сопоставление (Cross-Store Matching):**
   * В `NormalizerService` добавлены алиасы ключевых брендов (`Достык`, `Савушкин`, `ЭкоНива`, `Царь`, `Barilla`, `DEP`, `Новый День`, `3 Желания`, `Макфа`, `Акнек` и др.).
   * Токенизатор очищен от кавычек (`"`, `«`, `»`), что позволило находить идентичные SKU (`Сахар "ДОСТЫК" 3КГ` == `Сахар песок Достык 3кг/5`).
   * Число товаров, найденных сразу в 2+ сетях, выросло с **3 до 18** (включая DINA vs DANA и DINA vs FIX_PRICE).
